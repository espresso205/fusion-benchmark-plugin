# v5 与 v4：从单一准入评分到分开判断

v5 主要解决三件事：装配检查失败时保留可测分项；一个计算卡住时让其他独立计算继续；参考自身没有验收时不把比较结果发布为正式成绩。它没有自动修复参考模型，也不把几何相似度解释成工程装配合格。

|项目|v4|v5|
|---|---|---|
|启用方式|默认使用 v4/geometry|必须明确选择 `fusion-step-adapted-v5.0`；安装新版不会自动更改旧任务规则|
|候选有装配问题|严格检查失败会阻止计分|基础几何可用时继续测量；自交、干涉、零件匹配和配合单独报告|
|参考自身有问题|参考严格检查失败仍可能继续计算并给出比较分数|参考须经过绑定到具体文件的验收；未通过时总分为空，保留诊断测量|
|缺少一个主分项|缺项保持空值，以零贡献形成明确标注的下界总分|完整总分为空；另列已完成项的贡献下界，完整成绩均分不包含它|
|计算超时|逐题进程预算；某个调用卡住会占用后续阶段时间|各阶段在独立可终止进程内执行；默认阶段90秒、整题600秒，独立项目继续运行|
|质量计算|原v3/v4整体积分路径，复杂装配可能卡在整体Gauss–Kronrod调用|逐物理零件计算体积和惯性并合计，逐轮检查收敛；不收敛仍记缺测|
|装配结构|以几何有效性和实体干涉检查为主|保留实例和变换；增加一对一匹配、未匹配零件、重复件和配合检查|
|允许的配合交叠|没有本次新增的局部配合规则|绑定具体零件对、区域和体积上限；同一物理零件对只使用一次额度|
|总分含义|几何符合总分或缺项下界|完整的几何相似度；装配状态独立，不能用高分代替装配通过|
|结果报告|四视角和交互三维报告 `html-report/index.html`|独立静态报告 `report.html`，分开展示检查与测量；未迁移v4三维查看器|
|插件管理|v4结构化结果|补齐基础、装配、参考状态，下界和完整集合；能力实验身份同时绑定参考验收|

主分仍是形状、尺寸、质量，权重仍为6:5:2。形状和尺寸沿用v4算法；质量的计算路径改变。两版只允许整套模型刚体对齐，不接受缩放或镜像。源码、输入和对齐派生文件的身份检查继续保留，`ranking_eligible=false`。

v5没有运行v4的distance、face_match和section三项旧诊断。需要旧报告或复现历史结果时继续使用v4；不要把它们算成v5缺失的主分项。

## 如何使用

直接评测已有STEP：

```powershell
python -B evaluate.py --protocol fusion-step-adapted-v5.0 --cases C:/benchmark/cases.json --output C:/benchmark/results/new-v5 --timeout 600 --stage-timeout 90 --workers 4
```

在完整建模流水线的配置中设定：

```json
{"protocol":"fusion-step-adapted-v5.0","coordinate_mode":"geometry"}
```

管理MCP的 `start_run` 也支持这两个参数。参考登记须包含验收文件路径及其SHA256；具体结构、局部配合规则见[完整v5规则](SCORING_V5.md)。没有验收文件并不会自动通过，仍可以得到诊断测量。

## 使用边界

零件匹配依赖形状描述，尚不能完全区分“零件缺失”和“零件做错”。没有配合规则的题目不能取得完整装配通过。当前只执行冻结规则覆盖的配合，未定义的工程要求不能推断成已经检查。局部螺纹或密封交叠并不自动代表错误，必须按题目规则判断；没有整类标准件免检。

跨次运行缓存没有启用。阶段超时隔离确保其他项目继续，不保证每个复杂自交检查都能完成。v5提供可靠的检查状态和测量结果，完整题库验收仍须修复真实模型错误并补充配置、安装状态和配合依据。

复现旧榜单使用原GT和v4。使用修订GT或v5的新结果应单独报告，不能当成同一口径的模型提升。
